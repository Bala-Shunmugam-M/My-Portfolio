01

The gap in manual monitoring

Plant-health parameters — soil moisture, temperature, humidity, pH — change continuously. A human spot-check taken twice a day misses the window when soil moisture crashes or pH drifts into a harmful range. By the time the reading is taken, the damage is already happening.

02

The case for automated alerting

A microcontroller reads all four sensors continuously. The question is: can the system itself decide whether the current reading is abnormal — and notify the operator immediately, rather than waiting for the next manual check? That is the decision problem this project solves.

03

Why KNN?

KNN is a transparent, instance-based classifier with no strong distributional assumptions — it works well on a small labelled dataset where the decision boundary between NORMAL and ABNORMAL plant conditions is best understood by analogy to known examples. Interpretable, fast to iterate, and well-suited to the 701-sample scale.

The end-to-end anomaly detection pipeline

— Each stage hands off to the next; the final output is an operational decision
01Hardware — 4 sensors on Arduino — soil moisture (S), temperature (T), humidity (H), pH (P) stream readings over serial (COM3, 9600 baud)
02Python serial reader — parses the S / T / H / P byte stream, builds a feature vector per reading, feeds it to the classifier in real time · the integration point
03KNN classifier (scikit-learn, k = 5) — trained on 701 labelled readings (300 NORMAL · 401 ABNORMAL), Euclidean distance; predicts label 1 (NORMAL) or label 0 (ABNORMAL) for each new reading · the decision point
04Email alert (smtplib) — on an ABNORMAL prediction the program auto-sends an alert to the operator; no manual polling required
The pipeline is continuous: readings arrive, the classifier decides, and the alert fires automatically. The operator only acts when the system says to.

KNN classifier
scikit-learn k = 5 Euclidean distance

K-Nearest-Neighbours model

A KNeighborsClassifier (k = 5, Euclidean) trained on a 75 / 25 train/test split of 701 labelled readings. Each reading is a 4-feature vector [S, T, H, P]. Predictions: label 1 → NORMAL, label 0 → ABNORMAL. On the held-out 25% test set (176 readings) it scored 100% accuracy — but the dataset is small and cleanly separable, so the honest headline here is the working sensor → model → alert pipeline, not the score.

Alert layer
smtplib Automated email

Email alert on ABNORMAL prediction

When the classifier returns label 0 (ABNORMAL), the Python program immediately sends an alert email to the operator via smtplib. No dashboard polling, no manual check — the system surfaces the decision to the human automatically. The operator acts; the system decides when to alert.

Limitations & next steps

What this doesn't solve yet.

Current scope
Single-location demo25% test set

Single-node prototype

The system was built and validated as a single-location lab demo. It does not yet handle multi-sensor networks, sensor dropout, or production-grade data pipelines. It reached 100% on the held-out 25% split, but that reflects a small, cleanly separable dataset — it would not survive noisier real-world sensor data, which a larger labelled set and cross-validation would stress-test next.

Natural extensions
Threshold tuningDashboardMore sensors

Three clear upgrade paths

Threshold tuning — calibrate the ABNORMAL boundary per species or season. Additional sensors — light intensity, CO₂, EC could improve classification precision. Dashboard layer — a simple web view would replace raw email alerts with a historical record and trend visibility.
